# 11. Hancom Office 2024 Viewer Verification & Evaluation Guide

## 1. 검증 개요

본 인수인계 문서는 사용자가 **한컴오피스 2024 뷰어(또는 한글 2024)**에서 `debug/hwpx-overlap-mre/` 디렉토리에 생성된 6종의 진단 파일(`mre-A` ~ `mre-F`)을 직접 열람하여 비교 관찰할 수 있도록 작성된 실무 검증 가이드입니다.

**최종 판정 원칙**: 자동 테스트나 XML 속성 분석은 사전 증거일 뿐이며, **실제 한컴오피스 2024 뷰어 화면에서 시각적으로 확인된 결과만이 참(Truth)**입니다.

---

## 2. 파일 열람 준비

### 2.1 대상 파일 경로
저장소 루트 기준:
- `debug/hwpx-overlap-mre/mre-A-baseline.hwpx`
- `debug/hwpx-overlap-mre/mre-B-wrap-only.hwpx`
- `debug/hwpx-overlap-mre/mre-C-lineheight-only.hwpx`
- `debug/hwpx-overlap-mre/mre-D-font-only.hwpx`
- `debug/hwpx-overlap-mre/mre-E-geometry-only.hwpx`
- `debug/hwpx-overlap-mre/mre-F-combined.hwpx`

### 2.2 권장 뷰어 열람 모드
1. **보기 배율**: 100% 및 150% (글자 경계 및 간격 확대 관찰)
2. **조판 부호 / 문단 부호**: 켜기(Ctrl+G, C) 권장 (개행 발생 위치 직접 확인 가능)

## 3. 핵심 관찰 표적 및 단계별 체크리스트

### 관찰 구역 1 (Page 1): 단일행 라벨과 직하단 수치 충돌
- **표적 객체**:
  - `7:980` 라벨: `"균열밀도 (CDI)"` (글자 크기 8.25pt)
  - `7:981` 수치: `"0.031%"` (글자 크기 15.0pt, 세로 간격 6.0pt)
  - `7:988` 라벨: `"정제 검출 균열"` vs `7:989` 수치: `"1,248 개"`

| 파일 | 주요 확인 사항 | 예상 현상 및 판정 기준 |
|---|---|---|
| **A (Baseline)** | `7:980` 라벨이 한 줄인가, 두 줄로 꺾였는가?<br>아래 `0.031%` 수치를 침범/가리는가? | **[오류 재현]** "균열밀도 (CDI)"가 2줄로 꺾이면서 아래 "0.031%"의 상단 숫자와 겹침 |
| **B (Wrap Only)** | `7:980`이 `SQUEEZE`로 인해 한 줄로 유지되는가?<br>아래 `0.031%`와의 6pt 간격이 정상 확보되는가? | **[핵심 가설 B 검증]** 한 줄로 출력되며 수치와의 충돌이 해소되는지 확인 |
| **C (LineHeight Only)** | 2줄로 꺾이더라도 11.25pt 고정 행간 덕분에 침범 깊이가 줄어드는가? | **[핵심 가설 C 검증]** 충돌은 남아있으나 겹침 영역이 축소되는지 확인 |
| **D (Font Only)** | 맑은 고딕 매핑으로 글자 폭이 줄어들어 1줄로 유지되는가? | **[핵심 가설 D 검증]** 한글 폰트 변경만으로 개행이 억제되는지 확인 |
| **F (Combined)** | 라벨 1줄 유지 + 정상 행간 + 맑은 고딕이 결합되어 완전한 정상 렌더링이 나오는가? | **[종합 복구 판정]** 상용 보고서 수준의 무결성 달성 여부 확인 |

- **표적 객체**:
  - `7:998` 다중행 요약 본문: `"전반적인 외벽 균열 상태는 안전 범주에 있습니다. 최우선 보수 대상 동은 109동, 108동, 102동 순으로 도출되었습니다."`
  - `7:995` 배경 카드 및 `7:999` 직하단 간격 카드

| 파일 | 주요 확인 사항 | 예상 현상 및 판정 기준 |
|---|---|---|
| **A (Baseline)** | 160% 행간으로 인해 본문이 카드 하단을 벗어나 아래 객체를 침범하는가? | **[오류 재현]** 과다 행간에 의한 수직 팽창 여부 관찰 |
| **B (Wrap Only)** | `7:998`은 다중행이므로 여전히 정상적으로 여러 줄로 줄바꿈되는가? | **[보존 확인]** B에서 다중행이 1줄로 압축되는 부작용 없이 정상 개행되는지 확인 |
| **C (LineHeight Only)** | 행간이 11.25pt(고정)로 줄어들어 카드 안쪽에 안정적으로 수용되는가? | **[핵심 가설 C 검증]** 문단 높이가 줄어들어 카드 하단 여백이 회복되는지 확인 |
| **F (Combined)** | 다중행 본문의 줄바꿈과 행간이 가장 읽기 편하고 깔끔하게 렌더링되는가? | **[종합 복구 판정]** |

## 4. 검증 결과 피드백 양식

열람 후 다음 항목에 대해 관찰 결과를 공유해 주시면, 확인된 원인에 대해서만 프로덕션 렌더러에 정식 반영하겠습니다.

```text
[한컴 뷰어 검증 결과 공유]
1. 단일행 겹침 해소 여부:
   - mre-B (SQUEEZE): (해소됨 / 여전히 겹침 / 글자 압축이 너무 심함)
   - mre-C (행간 11.25pt): (완화됨 / 변화 없음)
   - mre-D (맑은 고딕): (해소됨 / 변화 없음)
   - mre-F (종합): (완전 해소됨 / 여전히 문제 있음)

2. 다중행 본문 (7:998) 상태:
   - mre-B: (정상 개행 유지 / 압축 왜곡 발생)
   - mre-C: (카드 안으로 안정적 수용 / 너무 빽빽함)

3. Page 2 배너 (7:1082) 수직 정렬:
   - mre-E: (아이콘 및 카드와 완벽 정렬 / 여전히 왜곡)

4. 가장 시각적으로 우수한 파일:
   - (mre-B / mre-E / mre-F 중 선택)
```
