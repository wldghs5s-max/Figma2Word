## 1. 5대 범주 정의 (Categorical Classification)

본 감사는 주관적 추측이나 이전 보고서의 낙관적 과장("100% 정상", "완전 해결")을 배제하기 위해 모든 정보를 다음 5개 범주로 엄격히 분류합니다:

1. **[U] 사용자 실제 확인 사실 (User-Verified Ground Truth)**: 사용자가 한컴오피스 2024 정식 뷰어(또는 MS Word)에서 직접 열어 눈으로 확인한 시각적/동작적 사실.
2. **[C] 코드에서 확인한 사실 (Code-Verified Fact)**: 리포지토리의 소스 코드와 Git 커밋 이력에 문자 그대로 존재하는 구현 사실.
3. **[R] 정품 문서에서 확인한 사실 (Reference-Verified Fact)**: 정상 동작하는 한컴 공식 생성 HWPX 파일(`완성본-20261012/report-1차-진단-편집가능-최종보정.hwpx`)의 XML에서 추출한 사실.
4. **[A] 자동 계산 결과 (Automated Calculation Result)**: Vitest 단위 테스트, TypeScript 컴파일러, 스크립트 실행 등 자동화 도구의 출력 결과.
5. **[H] 아직 검증되지 않은 가설 (Unverified Hypothesis)**: 원인 분석이나 해결책으로 제안되었으나 사용자 육안 검증 또는 표준 문서로 입증되지 않은 추정.

### Phase 22 (뷰어 호환성 복구)
- **[U] 사용자 실측 사실**: 한컴오피스 2024 뷰어에서 파일이 오류 없이 정상적으로 열림 (뷰어 크래시 및 파싱 거부 해소).
- **[C] 코드 사실**: `mimetype`, `version.xml`, `container.xml`, `manifest.xml`, `header.xml`의 네임스페이스 및 필수 스키마 구조 정규화 완료.
- **[A] 자동 계산 결과**: Vitest 362개 테스트 통과.

---

### Phase 23 (크로스포맷 렌더링 품질 개선)
- **[U] 사용자 실측 사실**: 한컴 뷰어로 확인 결과, 기존에 글자가 가로로 찌그러져 겹치던 압축 현상은 일부 완화되었으나, **줄바꿈이 발생한 문단이 바로 아래에 배치된 다른 문단이나 도형을 침범하여 글자가 중첩되거나 가려지는 심각한 2차 결함 발생**.
- **[C] 코드 사실**: `hwpxCanvasRenderer.ts`에서 `<hp:subList>`의 줄바꿈 속성을 `lineWrap="SQUEEZE"`에서 **모든 텍스트박스에 일괄적으로 `lineWrap="BREAK"`**로 변경함.
- **[A] 자동 계산 결과**: Vitest 362개 테스트 통과 (단위 테스트는 뷰어의 시각적 침범을 전혀 감지하지 못함).

---

### Phase 23.1 (Canonical Text Geometry & Overflow Recovery)
- **[U] 사용자 실측 사실**: 사용자가 한컴 뷰어에서 직접 확인한 결과, 텍스트 겹침 현상이 해결되지 않고 여전히 지속됨.
- **[C] 코드 사실**: 
  - `hh:paraPr`에 `snapToGrid="0"`, `breakSetting breakLatinWord="KEEP_WORD" breakNonLatinWord="BREAK_WORD"`, `autoSpacing eAsianEng="0" eAsianNum="0"`, 마진 0 적용.
  - `textMargin`의 좌우 기본값을 0으로 재설정.
  - CJK 문자 폭 추정치 조정.
- **[H] 당시 가설 (기각됨)**: "원고지 격자 스냅(snapToGrid=1)과 인위적 textMargin 패딩 때문에 텍스트 가용 폭이 줄어들어 불필요한 줄바꿈이 발생했을 것이다."
- **[U 대조 사실]**: 해당 타이포그래피 파라미터를 교정했음에도 불구하고 실제 뷰어에서 텍스트 겹침은 사라지지 않음.

---

### Page Orientation 긴급 조사 및 교정 (Commit `5ecc067`)
- **[U] 사용자 실측 사실**:
  - Figma 원본과 DOCX는 세로형인데, HWPX만 한컴 뷰어에서 가로형으로 열리고 있었음을 사용자가 최초로 발견하고 보고함.
  - 세로 방향 수정 적용 후: Stage 7 보고서의 **페이지 방향(세로 A4)과 전체 페이지 구성은 정상화되었으나, 텍스트 겹침 결함에는 변화가 없음**.
- **[C] 코드 사실**:
  - KS X 6101 OWPML 표준에서 `WIDELY`는 세로(Portrait), `NARROWLY`는 가로(Landscape)인데 기존 코드가 이를 반대로 코딩하고 있었음.
  - `landscapeAttr = isLandscape ? "NARROWLY" : "WIDELY"`로 교정하여 세로 문서가 정상 `WIDELY`로 직렬화됨.
- **[R] 정품 문서 사실**:
  - `report-1차-진단-편집가능-최종보정.hwpx`의 `<hp:pagePr>`은 `landscape="WIDELY" width="59530" height="84190"`로 세로형임.
