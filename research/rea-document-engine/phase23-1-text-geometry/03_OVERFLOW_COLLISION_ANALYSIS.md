# Phase 23.1 Text Overflow & Collision Classification Analysis

## 1. 개요 및 5대 오류 분류 체계

Phase 23.1 지침에 따라 텍스트 오버플로우, 침범, 충돌을 하나의 오류로 뭉뚱그리지 않고 아래의 5대 유형으로 엄밀히 구분하여 분석한다.

```text
┌────────────────────────────────────────────────────────┐
│               5대 기하학적 결함 분류 체계               │
├─────────────────────────┬──────────────────────────────┤
│ A. Horizontal Overflow  │ 가용 폭 초과 (단일행 라벨 폭 부족) │
│ B. Vertical Overflow    │ 개행 후 높이 초과            │
│ C. Inter-Element        │ 다운스트림 객체 영역 침범     │
│ D. Occlusion            │ 배경/장식 도형에 의한 가림    │
│ E. Source Geometry      │ 원본 Figma 데이터 자체 공간 부족│
└─────────────────────────┴──────────────────────────────┘
```

---

## 2. 유형별 심층 분석

### A. Horizontal Overflow (가용 너비 초과)
- **정의**: 단일행 라벨 또는 텍스트의 예상 렌더링 너비가 할당된 박스 너비보다 큰 경우.
- **실제 발생 사례**:
  - `7:959` ("`에어레카(AIREKA) · 드론 AI 외벽 균열 진단 · 넥스비전랩 · 펜테크`"):
    - 박스 폭: `195.7 pt`
    - 실제 한글 43자 필요 폭: `244.8 pt`
- **분석 및 해결**:
  - `snapToGrid="0"` 및 `eAsianEng="0"`을 적용하여 불필요한 자간 팽창을 원천 차단함.

### B. Vertical Overflow (개행 후 높이 초과)
- **정의**: 다중 줄 텍스트가 줄바꿈된 후 필요한 총 높이(`totalLines * lineHeight`)가 할당된 텍스트박스 높이(`bounds.height`)를 초과하는 경우.
- **수정 전 원인**:
  - `snapToGrid="1"`과 `KEEP_WORD`(어절 단위 개행)가 결합되어 행 끝에 빈 공백을 남기고 조기 개행되어 줄 수가 1~2줄 추가 팽창함.
- **수정 후 결과**:
  - `breakNonLatinWord="BREAK_WORD"` 적용으로 행 끝까지 글자가 채워져 불필요한 추가 행 발생이 억제됨.

### C. Inter-Element Collision (다운스트림 객체 침범)
- **정의**: 텍스트 요소의 수직 렌더링 범위가 아래에 위치한 다른 텍스트, 카드, 소제목의 경계 상자를 침범하여 겹치는 현상.
- **Stage 6 검증 결과**:
  - 수정 전: `Executive Summary` 문단이 4줄로 늘어나 하단 소제목과의 간격이 `3.0 pt`로 좁혀져 글리프 상하 충돌 발생.
  - 수정 후: 문단이 정격 3줄(`54 pt`)로 수습되어 하단 소제목과의 간격이 `21.0 pt`로 복구됨. 충돌 0건.

### D. Occlusion (객체 가림)
- **정의**: 텍스트가 z-order 상 뒤에 배치된 도형이나 불투명 채우기에 가려지거나, 회색 브러시로 덮여 사라진 것처럼 보이는 현상.
- **Phase 23 성과 계승**:
  - Phase 23에서 도입된 `<hc:fillBrush/>` 단독 닫힘 태그가 투명 배경 텍스트박스 주위의 불필요한 회색 테두리/채우기를 완벽히 제거함을 확인.
  - z-index 순서대로 정렬하여 텍스트가 카드 배경 상단에 정상 렌더링됨.

### E. Source Geometry Conflict (원본 데이터 공간 부족)
- **정의**: 렌더러의 변환 오차가 아니라, 원본 Figma 디자인에서 디자이너가 텍스트 높이나 간격을 실제 텍스트 분량보다 좁게 설정해 둔 경우.
- **Stage 7 Page 9 대표 사례**:
  - `7:952` ("`등급 A는 타 동 대비...`", 82자): 원본 Figma에 `height: 17px` (1줄)로 고정되어 있고, 바로 밑 `7:954` 제목이 `y=527pt`에 배치됨.
  - 실제 한글 82자는 499pt 폭에서 물리적으로 2줄이 필요함.
- **대응 원칙**:
  - Canvas IR 절대 좌표 원칙을 준수하여 렌더러가 주변 객체를 임의로 아래로 밀어내는 임시 조작을 일체 금지함.
  - `TextCollisionDetector`를 통해 원본 데이터 공간 부족을 사용자 및 감사자에게 명확히 보고함.
