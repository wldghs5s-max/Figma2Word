## 2. 핵심 범용 결함 심층 분석

### 2.1 결함 1: 소형 팝업/모달의 단독 페이지 배치 (`PAGE_GEOMETRY`)
- **현상**: Page 11 (`필터`, $504 \times 613$ px) 및 Page 13 (`사업정보 수정`, $504 \times 935$ px)은 대시보드 화면 위에 뜨는 모달 컴포넌트인데, 현재 파서의 `discoverPageFrames()`는 최상위의 모든 `FRAME`을 단독 인쇄 페이지로 변환하여 $5.25 \times 6.38$ 인치의 매우 작은 단독 페이지가 생성됨.
- **영향**: 문서 열람 시 페이지 크기가 급격히 변동되어 가독성이 떨어짐.

### 2.2 결함 2: 단일행 자동너비 텍스트의 폰트 치환 여백 압박 (`TEXT_WRAP` / `FONT_METRICS`)
- **현상**: Page 8, 10, 14, 15에서 테이블 헤더 및 뱃지 라벨이 Word의 DirectWrite 폰트 렌더러로 인해 글리프 너비가 1~3% 팽창하여 오른쪽 테두리에 아슬아슬하게 닿거나 부자연스러운 여백 부족을 보임.
- **기존 완충**: 직전 커밋에서 `Math.max(3, width * 0.03)`를 부여하여 줄바꿈은 막았으나, 텍스트 박스 내부 여백(`inset="0,0,0,0"`)과의 조화에서 미세 튜닝 여지가 있음.

### 2.3 결함 3: VML `<v:roundrect>`의 모서리 둥글기(Corner Radius) 비율 왜곡 (`STYLE_MISMATCH`)
- **현상**: Figma에서 `cornerRadius: 8`로 지정된 버튼이나 인풋 박스를 VML로 변환할 때:
  $$\text{arcsize} = \min\left(0.5, \frac{\text{cornerRadius}}{\min(w, h)}\right)$$
  으로 계산함. 그런데 높이가 32pt이고 너비가 200pt인 버튼의 경우, $\min(w, h) = 32$가 되어 $\text{arcsize} = 8 / 32 = 0.25$가 됨. VML의 `arcsize`는 직사각형의 짧은 변이 아니라 둘레 기준으로 해석되어 실제보다 훨씬 둥글게(타원형에 가깝게) 렌더링되는 왜곡이 발생함!
