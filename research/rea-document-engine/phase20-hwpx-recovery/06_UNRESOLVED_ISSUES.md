# Phase 20 Unresolved Issues & Technical Boundaries

본 문서는 Phase 20에서 해결된 영역과 아직 해결되지 않았거나 기술적 제약으로 인해 미검증으로 남겨진 항목을 투명하고 정직하게 보고한다.

---

## 1. 검증됨(Verified) vs 미검증(Unverified) 경계

### A. 검증 완료 (Verified via Code, Schema & Tests)
- **OWPML / KS X 6101 XML 적격성**:
  - `<hp:secPr>`의 `<hp:run>` 캡슐화.
  - 도형 자식 요소의 15단계 스키마 sequence 일치.
  - 사각형, 타원, 직선, 다각형, 그림 요소의 고유 지오메트리 및 속성 정합성.
  - 도형 ID의 `unsignedInt` 정수형 보장.
  - 7대 언어 대문자 열거형 선언.
  - 자동화 테스트 스위트(362건) 및 자체 검증 스크립트 전원 통과.

### B. 미검증 상태 (Unverified in GUI Viewer)
- **최신 한컴오피스 2024 뷰어에서의 시각적 화면 렌더링**:
  - 로컬 환경에 `HwpViewer.exe`가 설치되어 있음을 확인하였으나, 헤드리스 콘솔 세션의 제약으로 실제 창을 띄워 픽셀 단위 시각적 일치도를 자동 캡처하지 못함.
  - 따라서 **한컴 뷰어 화면의 시각적 레이아웃 충실도는 "미검증"**으로 분류하며, 추후 사용자가 GUI 세션에서 파일을 열어 확인해야 함.

## 2. 잔여 한계 및 기술적 부채 (Known Limitations)

### 1) 절대 좌표 캔버스 기반 직렬화 vs 네이티브 한글 표/문단 흐름
- **현재 구조**:
  - HWPX 렌더러는 Figma의 절대 좌표 캔버스 모델(`CanvasDocument`)을 `treatAsChar="0"`, `vertRelTo="PAPER"`, `horzRelTo="PAPER"` 속성을 가진 자유 배치 도형(`<hp:rect>`, `<hp:pic>`, `<hp:line>` 등)의 나열로 직렬화함.
- **영향**:
  - 시각적으로는 피그마 디자인을 원본에 가깝게 복원할 수 있으나, 한컴오피스에서 사용자가 본문 글을 수정하여 길어질 때 아래 개체들이 자동으로 밀려 내려가는 **"동적 문서 흐름(Flow Text Layout)"**은 지원되지 않음 (도형들이 고정 좌표에 머묾).
  - 네이티브 표(`<hp:tbl>`) 대신 선과 사각형 카드 기반의 복합 도형으로 표 형태가 렌더링됨.

### 2) 복합 다단(Multi-Column) 텍스트 흐름 미지원
- 하나의 텍스트 프레임 내에서 2단 또는 3단으로 자동으로 글이 넘치는 복합 컬럼 흐름은 현재 단일 `<hp:colPr colCnt="1"/>`로 고정되어 있음.

### 3) 비(非) A4 캔버스 비율 대응
- 사용자 요청 가이드라인에 따라 이번 임무에서는 비 A4 크기 대응은 범위 밖으로 설정됨. 현재 표준 A4 크기(595.28pt x 841.89pt) 또는 페이지 바운딩 박스를 기준으로 직렬화됨.

## 3. 향후 개선 로드맵 제안 (Phase 21+)

1. **GUI 환경 한컴 뷰어 시각 회귀 테스트 자동화**:
   - 대화형 윈도우 데스크톱 세션에서 `HwpViewer.exe` 또는 COM 객체(`HWPFrame.HwpObject`)의 `SaveAs` / `Print` API를 활용하여 PDF 또는 이미지로 변환 후 픽셀 비교를 수행하는 파이프라인 구축.
2. **도형 기반 표를 네이티브 `<hp:tbl>` 요소로 변환하는 하이브리드 파서 도입**:
   - 격자 구조로 정렬된 사각형 카드 군집을 인식하여 한컴 네이티브 표 태그로 재구성하는 기능 검토.
