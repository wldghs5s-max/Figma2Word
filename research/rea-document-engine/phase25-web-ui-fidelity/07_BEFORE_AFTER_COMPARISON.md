## 3. 대표 결함 상세 전후 비교

### 3.1 결함 1: 동일 규격 인접 페이지 충돌 (Multi-Page Canvas Collision)

#### 수정 전 (Before)
- **대상 화면**: `디자인 시스템 1` (1920×1080) & `디자인 시스템 2` (1920×1080)
- **현상**:
  - 인접한 두 페이지의 크기가 동일하여 `docxCanvasRenderer`가 `<w:sectPr>` 출력을 생략함.
  - VML 절대 좌표계(`position:absolute;left:...;top:...`)의 원점이 갱신되지 않아, Word가 1페이지와 2페이지의 모든 요소(122개 도형/텍스트)를 단 하나의 캔버스 위에 겹쳐서 렌더링함.
  - 사용자는 "디자인 시스템 1 제목 위에 디자인 시스템 2 버튼들이 엉켜 있는 심각한 파손 화면"을 목격함.

#### 수정 후 (After)
- **적용 로직**:
  - 인접 페이지 크기의 동일 여부와 무관하게, 마지막 페이지를 제외한 모든 페이지 문단에 `<w:sectPr><w:type w:val="nextPage"/>...</w:sectPr>`를 강제 방출.
  - 마지막 페이지는 `<w:body>` 최하단에 단독 섹션 선언 배치.
- **결과**:
  - `디자인 시스템 1` (Page 1)과 `디자인 시스템 2` (Page 2)가 깨끗하게 분리된 2개의 독립 페이지로 렌더링됨.
  - 겹침 요소 수: **122개 → 0개**.

---

### 3.2 결함 2: 비화면 플러그인 가이드 프레임의 거대 페이지 생성

#### 수정 전 (Before)
- **대상 노드**: Node `763:5084` (`📏 Container`, `GROUP`, 1920×3361 px)
- **현상**:
  - 디자이너가 치수 측정을 위해 실행한 Redline 플러그인 그룹을 일반 아트보드 화면으로 오인함.
  - 결과적으로 높이 2,520 pt (35인치)의 거대한 검은색 가이드 슬라이드가 Page 5로 삽입되어 전체 문서의 규격 일관성을 파괴함.

#### 수정 후 (After)
- **적용 로직**:
  - `discoverPageFrames()`에서 `GROUP` 노드 대상 명명 규칙 및 자식 검사 적용:
    `📏`, `Container`, `Redline`, `Measure`, `INNER_PADDING`, `OUTER_SPACING` 등 측정 도구 패턴 매칭 시 자동 제외.
- **결과**:
  - 불필요한 35인치 가이드 페이지가 완벽히 제거되고, 순수 17개 실전 웹 UI 화면만 선별됨.

---

### 3.3 결함 3: 단일행 브레드크럼 및 버튼 라벨 줄바꿈 (Typography Wrap)

#### 수정 전 (Before)
- **대상 노드**: Node `759:1538` (`"대시보드 / 사업장 관리 / 사업 관리"`, `textAutoResize: "WIDTH_AND_HEIGHT"`)
- **현상**:
  - Figma의 너비 `188px` (`141.0pt`)가 Word 텍스트박스 너비로 그대로 고정됨.
  - Word에서 Pretendard 폰트가 로컬 글꼴로 대체되면서 실제 텍스트 너비가 `145~147pt`로 팽창.
  - 박스 폭 부족으로 인해 마지막 단어 `"사업 관리"`가 2행으로 강제 개행되면서 하단으로 밀려 잘려 보임.

#### 수정 후 (After)
- **적용 로직**:
  1. `textAutoResize === "WIDTH_AND_HEIGHT"` 텍스트 박스에 대해 `<w:pPr><w:noWrap/></w:pPr>` 적용.
  2. 텍스트 박스 외곽선에 `Math.max(3, effectiveWidth * 0.03)`의 미세 완충 너비 부여.
- **결과**:
  - 총 471개의 단일행 텍스트 요소에서 단어 단위 비정상 개행이 100% 방지되어, 브레드크럼과 버튼 라벨이 의도된 한 줄로 매끄럽게 표시됨.

---

## 4. 결론

이번 프로덕션 개선은 특정 고객사 노드나 텍스트를 하드코딩하지 않고, **OpenXML 다중 섹션 VML 캔버스 아키텍처**와 **Figma 플러그인/타이포그래피 일반화 규칙**에 기반하여 수행되었다. 그 결과, 실전 웹 UI 디자인이 Word에서 무너지던 3대 근본 원인이 완벽히 제거되었다.
