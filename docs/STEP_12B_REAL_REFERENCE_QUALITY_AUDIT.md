## 4. 식별된 핵심 충실도 결함 및 일반화된 코드 개선

실제 피그마 정답 라이브 데이터 및 기준 문서 대조 과정에서 도출된 핵심 결함을 일반화된 규칙으로 수정했습니다.

### 결함 1: 단일 텍스트 노드 개행 문자(`\n`) 증발 및 장문 본문의 제목 오분류
- **원인**:
  - OpenXML 사양상 `<w:t>` 태그 내부의 `\n`은 단순 공백으로 무시되어 Word 상에서 모든 줄바꿈이 한 줄로 뭉개짐.
  - 디자이너가 긴 텍스트 첫머리에 "Document Title:" 등을 기입하면 Figma가 레이어 이름을 해당 텍스트로 자동 명명함. 공백/개행 차이로 인해 레이어 이름 일치 감지(`nameMirrorsText`)가 실패하여 1,798자에 달하는 10페이지 분량의 긴 본문 전체가 단 하나의 `Heading 3`으로 잘못 변환됨.
- **해결 (`docxRenderer.ts`, `figmaParser.ts`)**:
  - `renderTextRun`에서 `\n`을 감지하여 각 줄을 분할하고 `<w:br/>` (`break: 1`) 태그를 명시적으로 삽입 (연속 개행 `\n\n` 빈 줄도 보존).
  - `isHeadingText`에 일반화된 본문 가드를 적용하여 150자 초과 또는 2회 이상 개행 포함 시 본문(`paragraph`)으로 처리하고, 공백을 정규화(`\s+`)하여 자동 명명된 레이어 오탐을 완벽 차단.

### 결함 2: 네이티브 테이블 기본 셀 여백(`<w:tblCellMar>`) 누락
- **원인**:
  - `renderTable`에서 `new Table(...)`에 `margins`가 지정되지 않아 OpenXML `<w:tblCellMar>` 속성이 누락되고, 개별 셀에 명시적 패딩이 없으면 Word가 0pt 마진을 적용하여 텍스트가 표 테두리 선에 달라붙는 시각적 답답함 발생.
- **해결 (`docxRenderer.ts`)**:
  - `renderTable`의 `new Table(...)`에 전문 비즈니스 문서 표준 기본 셀 여백(`margins: { top: ptToDxa(5), bottom: ptToDxa(5), left: ptToDxa(8), right: ptToDxa(8) }`, 상하 100 dxa / 좌우 160 dxa)을 기본 탑재.

### 개선 3: 파이프라인 레벨 문서 페이지 여백(`marginsMm`) 설정 지원
- **해결 (`src/pipeline/index.ts`)**:
  - `PipelineOptions`에 `marginsMm` 옵션을 추가하여, Figma에서 전체 캔버스를 꽉 채워 설계된 전문 보고서(A4 규격 794×1123) 변환 시 불필요한 기본 25.4mm(1인치) 여백으로 인한 세로 페이지 넘침 현상을 유연하게 제어할 수 있도록 지원.
