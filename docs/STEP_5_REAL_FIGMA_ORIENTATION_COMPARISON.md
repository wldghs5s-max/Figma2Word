## 4. 프레임 단위 비교 및 좌우 배치 분리 현상 정밀 분석

### 4.1 사용자가 제기한 핵심 문제
> "하나의 Figma 프레임에서 좌우에 배치된 콘텐츠가 Word의 서로 다른 페이지로 분리되는 현상"

### 4.2 원인 구분 및 진단 결과

| 구분 항목 | 검증 및 발생 여부 | 원인 상세 분석 |
|---|---|---|
| **A. 프레임 분할 및 화면 그룹핑 문제** | **주요 원인 아님 (정상)** | `parseCanvasChildren`의 명시적 `<w:br w:type="page"/>` 17개는 모두 독립된 최상위 아트보드(메인 랜딩, 회원가입, 마이페이지, 이용약관 등) 경계에만 삽입되었으며, 단일 화면 내부에서 오탐으로 삽입된 페이지 나눔은 없음. |
| **B. Word 본문 가용 폭 부족** | **부분적 기여** | Portrait(451pt)에서는 데스크톱(1440px)의 600px+600px 2열 배치가 225pt 이하로 극단 압축되어 텍스트와 이미지가 아래로 길어지면서 페이지를 넘길 위험이 높음. 가로형(698pt)에서는 가용 폭이 54.6% 증가하여 이 압박이 크게 완화됨. |
| **C. 테이블 및 컬럼 폭 계산 문제** | **핵심 원인 1** | `LayoutEngine.clusterHorizontalRows`는 비-오토레이아웃 절대 좌표 요소 간 수직 겹침(`vOverlap > 10`) 및 Y좌표 근접성(`rowYThreshold`)을 기준으로 가로 행으로 묶음. 그러나 피그마 원본에서 좌우 카드가 비대칭 높이를 갖거나 수직 정렬이 어긋난 경우 가로 행 클러스터로 묶이지 못하고 **수직 순차 요소**로 처리됨. 수직 순차 요소가 되면 각각 독립된 100% 폭 테이블 또는 블록으로 렌더링됨. |
| **D. Word 자동 페이지 나눔 (세로 높이 초과)** | **핵심 원인 2** | 가로 행으로 묶이지 못한 두 개의 큰 카드(예: 이미지 219pt + 텍스트 150pt = 높이 369pt)가 순차 배치될 때, 가로형 문서의 가용 높이(451.3pt)를 초과하게 되므로 Word 렌더러가 두 번째 카드를 다음 페이지로 자동 넘김(Natural Page Break). 가로형은 가로폭이 넓어진 대신 세로 높이가 698pt → 451pt로 줄어들었기 때문에, 수직 순차 블록의 페이지 분리가 더 자주 발생함 (98페이지 → 137페이지 증가의 근본 이유). |

### 4.3 결론
- 단순히 "가로형 페이지로 변경"하는 것만으로는 C(비대칭 좌우 요소의 가로 행 인식 실패)와 D(세로 가용 높이 감소에 따른 자연 개행)를 완전히 해결할 수 없음.
- 좌우 요소가 동일 행 테이블(`Row Cluster`)로 묶인 경우(Table #23, Table #24)에는 가로형에서 완벽하게 넓은 좌우 2열/3열로 나란히 유지됨.
- 반면 가로 행 클러스터링을 타지 못한 큐레이션 카드의 경우 각각 세로 블록으로 렌더링되어 페이지가 분리됨.
