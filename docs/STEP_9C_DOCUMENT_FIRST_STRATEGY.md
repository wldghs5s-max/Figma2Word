## 1. 프로젝트의 공식 목표 (Official Project Goals)

### 1.1 최초 개발 동기 및 비즈니스 배경
- 실무 및 사업 환경에서 제안서, 보고서, 사업계획서, 분석설계서 등을 작성할 때, 고성능 대형 언어 모델(Claude 3.7 Sonnet, GPT-4o 등)에게 원본 Figma 디자인 전체(JSON 스냅샷 및 대용량 고해상도 이미지)를 입력하고 Word(`.docx`)나 HWPX 문서를 처음부터 재구성하도록 요청하면 **매회 막대한 AI 토큰 비용과 긴 대기 시간**이 소모된다.
- 이를 해결하기 위해, 반복적으로 발생하는 디자인 해석과 문서 변환 작업을 **재사용 가능한 결정론적(Deterministic) 로컬 TypeScript 엔진**으로 흡수한다.
- 고성능 AI는 전체 문서를 밑바닥부터 다시 그리는 것이 아니라, 로컬 엔진이 고품질로 변환한 Word 산출물을 바탕으로 내용 검토와 미세 서식 교정만 수행하도록 하여 **AI 토큰 소비를 80% 이상 절감**하는 것이 프로젝트의 핵심 목적이다.

### 1.2 "품질 희생 없는 비용 절감" 절대 원칙
- 본 프로젝트는 단순한 Figma 디자인 미리보기 도구나 저품질 초안 생성기가 아니다.
- **품질을 희생하여 비용을 낮추는 것은 프로젝트 성공으로 간주하지 않는다.**
- 변환 품질이 낮아 AI가 Word 문서를 처음부터 다시 분석하고 전면 재작성해야 한다면 토큰 절감 목적 자체가 완전히 무력화되기 때문이다.
- 따라서 변환 엔진은 원본 문서 디자인의 시각적 충실도와 Word 네이티브 편집성을 철저히 보존해야 한다.

## 3. 문서형(Priority A) 및 일반 UI(Priority B) 지원 우선순위 및 품질 목표

### 3.1 Priority A — 문서형 Figma 디자인 (최우선 지원 대상)
- **지원 대상**:
  - 사업 제안서 (Proposals)
  - 사업계획서 (Business Plans)
  - 업무 보고서 (Business Reports)
  - 시스템 분석/설계서 (Architecture / Spec Documents)
  - A4 규격 기반 문서 템플릿
  - 기타 Word/HWPX 출력을 염두에 두고 제작된 프레임
- **품질 목표**:
  1. **페이지 규격 및 경계 보존**: A4 (Portrait: 210×297mm / Landscape: 297×210mm) 규격, 여백(Margin), 헤더/푸터 영역 엄격 준수.
  2. **Word 네이티브 편집성**: 텍스트(Heading/Paragraph), 표(Table), 리스트(Bullet)를 100% 네이티브 OpenXML 객체(`w:p`, `w:r`, `w:tbl`)로 생성.
  3. **서식 정밀도**: 폰트 패밀리, 크기, 색상, 자간/행간, 정렬, 셀 패딩, 테두리(Border) 무손실 재현.
  4. **표(Table) 구조 정밀 변환**: 다단/다행 병합(Colspan, Rowspan), 셀 배경색, 테두리 두께 보존.
  5. **결정론적 안정성**: 동일한 입력에 대해 항상 100% 동일한 DOCX 바이트/구조 산출.
  6. **AI 토큰 절감 지표**: AI가 문서를 밑바닥부터 작성할 때 대비 토큰 소비 80% 이상 절감.

### 3.2 Priority B — 일반 UI Figma 디자인 (보조 지원 대상)
- **지원 대상**: 웹사이트, 모바일 앱 화면, 대시보드 콘솔, Bento Grid 등 디지털 스크린 디자인.
- **품질 목표**:
  1. 주요 섹션, 카드 컨테이너, 텍스트, 이미지의 시각적 레이아웃 형태 유지.
  2. 현재 Step 8D까지 확보된 Figma Grid Bento 복구, Row 클러스터링, 다단 테이블 레이아웃 기능의 안정적 유지.
  3. **개발 경계**: 웹 UI 전반에 대해 브라우저 렌더링과 1:1 픽셀 단위로 일치시키기 위해 파이프라인 복잡도나 개발 일정을 무한정 확장하지 않음.

## 6. Step 9B 결과의 공식적 해석 및 품질 측정 계획

### 6.1 Step 9B 검증 결과의 공식적 해석
- Step 9B에서 도출된 시각적 검증 결과는 1216px 이상의 넓은 데스크톱 웹 UI 화면(Bento Grid, 마이페이지, FAQ, 관리자 테이블 등)을 A4 용지에 맞추는 과정에서 발생한 계측 결과임.
- 이는 **"Priority B(웹 UI) 대상에 대한 현재 레이아웃 엔진의 축소·재배치 특성 확인"**이며, **"Figma2Word 엔진의 최종 문서 변환 품질 한계"가 아님**.
- 또한 Step 9B의 비교 검증은 Figma 웹 캔버스의 라이브 고화질 래스터 캡처와 1:1 픽셀 매칭한 것이 아니라, OpenXML 구조 및 Microsoft Word COM 실제 렌더링(WinRT PDF)을 기반으로 계측되었음을 명확히 기록함.

### 6.2 문서형 디자인(Priority A) 품질 측정 계획
1. **페이지 경계 및 여백 일치율**:
   - Figma 프레임 크기 대비 Word 페이지 섹션 크기 및 마진(상/하/좌/우)의 일치도 검증.
2. **논리적 읽기 순서 (Reading Order)**:
   - 다단 컬럼 및 텍스트 블록이 Word 문단 순서에서 자연스럽게 위→아래, 좌→우로 흐르는지 검증.
3. **표(Table) 변환 완전성**:
   - Figma 내 그리드/테이블 컴포넌트가 Word 네이티브 `w:tbl`로 변환되어 셀 너비, 정렬, 테두리가 유지되는지 검증.
4. **Word 네이티브 편집성 점수**:
   - 전체 텍스트 및 표 요소 중 래스터 이미지로 변환되지 않고 직접 수정 가능한 네이티브 텍스트/표의 비율 (목표: 95% 이상).
5. **AI 토큰 절감률 측정**:
   - 동일 문서를 LLM API로 직접 DOCX 생성 시 소모되는 입출력 토큰 대비, Figma2Word 로컬 변환 파이프라인 사용 시의 토큰 절감율 산출 (목표: 80% 이상 절감).

## 7. 다음 구현 단계의 최소 범위 (Next Implementation Scope)

1. **문서형 전용 레이아웃 규칙 (Document-First Layout Rules)**:
   - A4 프레임 감지 시 웹 반응형 축소 로직 대신 문서 전용 1:1 페이지 매핑 활성화.
2. **다중 프레임 순차 페이지네이션 (Multi-Frame Page Break Strategy)**:
   - Figma 상의 여러 A4 프레임(페이지)을 Word의 논리적 페이지 나눔(`w:br type="page"`)으로 깔끔하게 연결.
3. **텍스트 스타일 계층 구조 (Semantic Heading Hierarchy)**:
   - 폰트 크기 및 가중치에 따라 Word 기본 스타일(`Heading 1`, `Heading 2`, `Normal`)과 자동 연동.
4. **문서 표(Table) 전용 파서 강화**:
   - 행·열 구조를 가진 Figma 컴포넌트를 Word 테이블 그리드로 안전하게 직렬화.
