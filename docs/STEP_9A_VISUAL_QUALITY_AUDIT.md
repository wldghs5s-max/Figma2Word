### 3.1 Screen 1: 큐레이션 Bento Grid (`1:4540` / `1:4543`) — Page 3

#### A. 레이아웃 (Layout)
- **전체 폭 및 높이**: 부모 컨테이너 폭 1216px가 Word 본문 폭(A4 Portrait 기준 100% = 4513 dxa)으로 균등 스케일됨.
- **좌우 2열 분할**: 외부 테이블이 정확히 `50% : 50%` (`4513 dxa` 좌우)로 분할됨.

- **여백 및 간격**: 카드 간 가로 16px, 세로 16px 간격이 셀 마진과 테이블 간 단락 마진으로 자연스럽게 표현됨. 이전 Step 8B에서 발생했던 308px의 거대한 수직 빈 공간이 완전히 제거됨.

#### B. 텍스트 (Text)
- **글꼴**: `WenQuanYi Zen Hei` (미설치 시 Word 기본 맑은 고딕으로 매핑).
- **글자 크기 & 굵기**: 타이틀 `16px` $\rightarrow$ `12pt`, 본문 설명 `14px` $\rightarrow$ `10.5pt`, 헤더 `3D646C` (다크 틸), 카드 타이틀 `FFFFFF` (화이트 볼드) 정상 적용.

#### C. 도형 및 이미지 (Shapes & Images)
- **이미지 종횡비**:
  - 카드 0: 600×600 (1:1) $\rightarrow$ DrawingML `cx=5715000, cy=5715000` (정사각형 유지).
  - 카드 1: 600×292 (2.05:1) $\rightarrow$ DrawingML `cx=5715000, cy=2781300` (와이드 유지).
  - 카드 2, 3: 292×292 (1:1) $\rightarrow$ DrawingML `cx=2781300, cy=2781300` (정사각형 유지).
- **배경 및 모서리**: 카드 하단 텍스트 영역의 블랙 반투명 오버레이(`000000`)가 1x1 테이블 음영(`w:shd w:fill="000000"`)으로 구현됨. Figma의 `cornerRadius: 24`는 Word OpenXML 테이블 사양상 직각 모서리로 렌더링됨.

#### D. 편집 가능성 (Editability)
- 4개 카드의 텍스트 전체(제목, 설명 문구)가 Microsoft Word에서 직접 클릭하여 수정 가능한 일반 단락으로 보존됨.

## 5. 문제점 분류 및 우선순위 (Issue Prioritization)

### P0 (문서 손상, 콘텐츠 누락): **0건 (None)**
- 손상 경고 0건, 누락 텍스트/이미지 0건.

### P1 (심각한 레이아웃 파괴): **0건 (None)**
- Step 8D에서 큐레이션 Bento Grid 및 숙소 히어로 갤러리의 붕괴 현상이 완벽히 해결됨.

### P2 (크기, 간격, 정렬, 스타일 불일치): **2건**
1. **[P2-1] Desktop 와이드(1280px) 웹 화면의 Portrait 축소에 따른 페이지 연장**:
   - **현상**: A4 Portrait 인쇄 폭(159.2mm)에 1280px 데스크톱 레이아웃을 담으면서 열 너비가 좁아져, 일부 3~4열 카드나 긴 상세 페이지가 세로로 여러 장에 걸쳐 늘어남.
   - **원인**: 용지 방향에 따른 종횡비 차이 (가로 폭 부족).
   - **대응 방안**: Desktop 웹 디자인 변환 시 UI에서 **Landscape (A4 가로, 246mm 폭)**를 기본 추천값으로 설정하거나 자동 전환 안내 제공.
2. **[P2-2] 비대칭 셀 높이 차이로 인한 하단 수직 여백**:
   - **현상**: 2열 테이블에서 좌측 셀의 콘텐츠가 우측 셀보다 길 때, 우측 셀 하단에 Word 표 특유의 빈 수직 공간이 남음.
   - **원인**: Word OpenXML 테이블 행은 해당 행 내 '가장 높은 셀'의 높이에 맞춰지는 사양적 한계.
   - **대응 방안**: 현재 구현된 Bento 중첩 방식이 이를 최소화하고 있으며, 추가적인 분할은 불가피한 구조임.

### P3 (사소한 시각적 차이): **2건**
1. **[P3-1] 카드 모서리 둥글기(Corner Radius) 미지원**:
   - **현상**: Figma 카드의 둥근 모서리(`cornerRadius: 24`)가 Word에서는 직각 테두리로 표현됨.
   - **원인**: Word OpenXML 표 셀(`<w:tc>`)은 CSS `border-radius`를 지원하지 않음. (VML 도형으로 변환 시 텍스트 흐름과 편집 가능성이 파괴되므로 현재의 표 셀 방식이 가장 표준적임).
2. **[P3-2] 사용자 PC 미설치 폰트의 시스템 대체**:
   - **현상**: `WenQuanYi Zen Hei` 또는 `Plus Jakarta Sans`가 미설치된 PC에서 Word가 `맑은 고딕` 또는 `Calibri`로 대체 표시함.
   - **대응 방안**: OpenXML `w:rFonts`에 한글 표준 폰트(맑은 고딕)를 보조 폰트(`w:eastAsia`)로 함께 지정하는 방안 검토.
