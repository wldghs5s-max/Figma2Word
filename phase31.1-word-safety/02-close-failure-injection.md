# 02. Word Close Failure Path Injection Testing (C1 ~ C6)

## 1. Objective & Audit Finding

While Phase 31 prevented deletion when `handle.lifecycleState === 'uncertain'`, it did not verify the end-to-end execution of `closeTargetDocOnly()` when an exception occurs inside `captureWordState()`.

In Phase 31.1, we introduced `WordAutomationCloseDeps` into `closeTargetDocOnly()` to execute controlled failure injection across all close paths:

```typescript
export interface WordAutomationCloseDeps {
  runAppleScript?: (script: string, timeoutMs?: number) => string;
  captureWordState?: () => WordEnvironmentSnapshot;
}
```

## 3. Detailed Analysis of Test C5 (TARGET_NOT_FOUND)

`TARGET_NOT_FOUND` occurs when Word's document loop does not match `handle.normalizedPosixPath`.
- **Benign Case (5a)**: The document was already closed (e.g. user manually closed it, or Word closed it on save). Word's open paths list does NOT contain the path. Disposition: The document is confirmed absent from Word (`'close_confirmed'`). It is safe to clean up.
- **Pathological Case (5b)**: Word failed to match the path in AppleScript, yet `captureWordState()` confirms the document is still open. Disposition: **Fail-Closed**. The handle transitions to `'uncertain'`, throws an error, and disk cleanup is strictly refused.

## 4. Test C6 (Protection of User Documents)

The AppleScript generated by `closeTargetDocOnly` contains:
```applescript
repeat with i from 1 to (count of documents)
  set d to document i
  set matchConfirmed to false
  try
    set p to (posix full name of d as text)
    if p is equal to "<escapedTarget>" then
      set matchConfirmed to true
    end if
  end try

  if matchConfirmed then
    close d saving no
    set targetFound to true
    exit repeat
  end if
end repeat
```
- Only matches against the exact POSIX path of our isolated document.
- Never iterates over or closes documents not matching the exact target POSIX string.
- Eliminates any risk of global `close every document` commands.
