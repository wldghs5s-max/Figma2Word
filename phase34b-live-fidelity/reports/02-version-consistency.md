# 02. Figma Server Version vs. Local Snapshot Consistency Analysis

## 1. 개요 및 배경

Figma 디자인은 클라우드 상에서 지속적으로 수정될 수 있는 동적 자산입니다.
현재 로컬에 보관된 디자인 데이터는 약 186.52MB 크기의 정적 스냅샷(`펜테크 3차 디자인.json`)을 기반으로 하고 있습니다.

만약 클라우드의 실제 Figma 파일이 스냅샷 추출 이후 디자이너에 의해 수정되었다면, 실제 API를 통해 수집된 PNG와 기존 Word 출력 결과 사이에 시각적 차이가 발생할 수 있으며, 이 차이는 렌더러의 버그가 아니라 **디자인 자체의 변경(Design Drift)**에 기인한 것입니다.

따라서 시각적 충실도(SSIM, MAE)를 왜곡 없이 측정하기 위해서는 **서버 원본과 스냅샷의 버전 정합성(Version Consistency)**을 반드시 규명해야 합니다.

---

## 2. 조사된 메타데이터 및 분석 결과

1. **로컬 스냅샷 식별자**:
   - 파일명: `펜테크 3차 디자인.json`
   - 스냅샷 기준 파일키: `pentech_v3_snapshot` (가상 키)
   - 크기: 195,582,942 bytes (186.52 MB)
   - 17개 타겟 프레임의 고유 ID 및 Bounding Box가 확정되어 있음.
2. **Figma REST API v1의 버전 파라미터 지원 규격**:
   - Figma Images API 엔드포인트:
     `GET /v1/images/:file_key?ids=...&format=png&version=:version_id`
   - Figma 공식 규격에 따르면, `version` 쿼리 파라미터를 제공할 경우 최신 상태가 아닌 **특정 시점의 파일 버전 히스토리 ID에 대응하는 렌더링 결과**를 반환하도록 지원합니다.
3. **현재 판정 상태**:
   ```text
   VERSION_MATCH: UNVERIFIED
   ```
   - 실제 네트워크 조회가 이루어지지 않은 Stage 1 시점에서는 서버 원본의 최신 `lastModified` 시각과 버전 ID를 조회할 수 없으므로 `VERSION_MATCH_UNVERIFIED`로 엄격히 유지합니다.

---

## 3. Stage 2 라이브 수집 시 버전 정합성 확인 계획

Stage 2 실행 시 다음 절차를 통해 버전 정합성을 확인합니다:

1. **사용자가 제공한 실제 Figma URL / fileKey 확인**:
   - URL 내에 특정 버전 태그나 히스토리 노드가 포함되어 있는지 분석.
2. **Figma API 응답 메타데이터 검증**:
   - 이미지 다운로드 후 렌더링된 요소의 구조(폰트 크기, 프레임 이름, 주요 배너 레이아웃)가 스냅샷 메타데이터와 현저한 차이가 있는지 검사.
3. **불일치 감지 시 대응 방침**:
   - 만약 17개 프레임 중 주요 컴포넌트의 위치나 텍스트가 명백히 변경된 사실이 확인될 경우, 판정을 `VERSION_MISMATCH_CONFIRMED`로 전환.
   - 변경된 프레임에 대해서는 렌더러 결함과 원본 변경 오차를 엄격히 분리하여 보고.
   - 임의로 로컬 스냅샷을 덮어쓰거나 인위적으로 정답 점수를 조작하지 않음.
