## 2. 4대 공통 렌더링 결함 심층 분석

### 2.1 결함 1: 문서 격자 스냅(`snapToGrid`)에 의한 텍스트 행간 수직 점프
- **현상**: VML `<v:textbox>` 내부에 명시된 문단(`<w:p>`)이 Word에서 렌더링될 때, 사용자가 지정한 서브픽셀 좌표와 다르게 약 2~4pt 위나 아래로 미세하게 밀리는 현상이 발생함.
- **원인 분석**:
  - Microsoft Word는 기본적으로 페이지에 가상의 12pt 기본 격자(Document Grid)를 유지합니다.
  - `<w:pPr>` 내부에 명시적으로 `<w:snapToGrid w:val="0"/>`을 선언하지 않으면, Word 렌더러는 문단 텍스트를 가장 가까운 문서 격자선으로 강제 스냅(Snapping)시킵니다.
  - 이로 인해 Figma 디자인에서 정밀하게 계산된 수직 중앙 정렬(`v-text-anchor:middle`) 및 카드 내부 패딩이 수직으로 어긋나는 왜곡이 발생했습니다.

### 2.2 결함 2: 단일행 자동너비 텍스트의 글리프 치환 여백 압박 및 줄바꿈
- **현상**: 한 줄 버튼 레이블, 뱃지, 테이블 헤더 텍스트가 오른쪽 끝에서 미세하게 잘리거나 원치 않는 2행으로 강제 개행됨.
- **원인 분석**:
  - Figma의 브라우저 폰트 렌더러와 Windows Word의 DirectWrite 엔진 간에는 글리프 폭 계산에 1~3%의 미세 편차가 존재합니다.
  - 특히 CJK 한글 글리프의 경우 시스템 폰트 대체(Pretendard → 맑은 고딕) 시 자간 폭이 미세하게 증가합니다.
  - 박스 너비가 Figma 수치 그대로 고정되어 있으면 Word는 공간 부족으로 판정하여 단어 줄바꿈을 유발합니다.
  - `<w:wordWrap w:val="0"/>` 및 비례 완충 여백(Horizontal Buffer)의 정밀 조율이 필수적입니다.

### 2.3 결함 3: VML `<v:roundrect>`의 arcsize 계산 한계 및 서브픽셀 정밀도
- **현상**: 높이가 작은 직사각형(예: 높이 32pt, 너비 200pt)의 버튼에서 모서리 둥글기가 지나치게 원형으로 변형되거나, 반대로 큰 카드에서 곡률이 충분히 표현되지 않음.
- **원인 분석**:
  - VML 스펙에서 `arcsize`는 직사각형의 짧은 변($\min(w, h)$) 대비 모서리 반경($R$)의 비율로 정의되며, 유효 범위는 $0.0$부터 $0.5$까지입니다.
  - 요소 크기가 극단적으로 작거나($\min(w, h) \to 0$) `cornerRadius`가 반경 상한을 초과할 때 분모가 0이 되어 `NaN` 또는 비정상적인 속성이 생성될 수 있는 취약점이 존재했습니다.

### 2.4 결함 4: 소형 팝업/모달의 단독 페이지 배치 기하학 편차
- **현상**: Page 11 (`필터`, $504 \times 613$ px), Page 13 (`사업정보 수정`, $504 \times 935$ px) 등은 대시보드 화면 위에 뜨는 모달 다이얼로그인데, Word에서 독립된 전체 페이지로 렌더링되면서 뷰포트 종횡비가 달라져 배경 여백이 크게 산출됨.
- **원인 분석**:
  - Figma 파서의 페이지 프레임 선별 단계에서 최상위 아트보드를 그대로 1개 페이지로 변환하기 때문에 발생하는 뷰포트 아키텍처적 특성입니다.
